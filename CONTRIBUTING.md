# Contributing

Thanks for reading this far. The project stays small on purpose, so the rules are simple.

- One idea per change. Small pull requests get reviewed and merged. Big ones sit.
- Tests ship with the change. A fix without a test is a hope, not a fix.
- The score stays explainable. Any new finding names the numbers behind it.
- Nothing in this project writes to a table. A change that adds a write path needs a design discussion first.
- Commit messages say what changed and where, in plain words, on the first line. The body says why and how it was checked.
- Branch names say the kind of work, the ticket, and the topic. A few plain words are enough.
